# 网页端 AG-UI 新对话模式：前端预适配

日期：2026-09-21（北京时间）。本文先记录网页端预适配阶段，后续更新记录正式切换代码；手机端不在本轮范围内。

接口依据：[新架构前端接口文档，固定提交 2942068](https://github.com/lin1244643637/duizhangAgent/blob/294206833a8dd9a01c199eadefe242d60e5d5486/docs/api/new-architecture-frontend-api.md)。

> 2026-09-22 更新：网页端已完成正式切换代码。以下“预适配”内容保留为历史记录；当前行为以“正式切换”一节为准。

## 正式切换（2026-09-22）

- 新建会话和历史会话的后续纯文本消息默认请求 `POST /api/v1/agui/runs`，不再显示实验模式选择器。紧急回退时显式设置 `VITE_AGUI_CHAT_ENABLED=false` 并重新构建。
- 文件上传继续复用现有异步上传接口，上传任务完成后的下一轮文本对话仍走 AG-UI；历史加载、会话删除、消息删除和任务轮询继续复用现有能力。
- 支持 `RUN_ERROR` 终态、精确事件游标重连、服务端取消、结构化澄清和审批确认。审批提交到 `POST /api/v1/agent-runs/approve-action`，随后使用相同 run 和 `Last-Event-ID` 继续接收事件。
- 保留真实 SSE 接收和前端轻量打字机，去除“直接显示全部”；用户上翻后停止自动跟随，生成过程中用右下角圆形向下箭头返回底部。
- 手机端不在本轮范围内；真实账号端到端联调与生产验收在发布流程中单独执行。

## 入口与启用

- 默认保持标准对话；默认不显示实验入口。
- 本地或联调环境显式设置 `VITE_AGUI_CHAT_ENABLED=true`，重启开发服务（部署产物需重新构建），新建空白对话后选择“新对话模式（实验）”。例如：`VITE_AGUI_CHAT_ENABLED=true npm run dev`。
- 发送第一条消息后固定当前会话模式；历史会话不迁移，新建下一会话仍默认标准模式。
- 此开关只开放前端入口，不代表后端已启用新架构；不要在尚未联调的生产环境打开。

## 已实现

- 复用现有输入框、Markdown、结构化回复和分析活动组件，不引入新的 UI 框架或 AG-UI SDK。
- 使用现有鉴权流请求封装发送 POST `/api/v1/agui/runs`。每个会话固定 `threadId`，每轮新建 `runId`，请求只发送文档允许字段。
- 处理文本、工具状态、安全结果说明、结构化快照、审批等待、完成及失败事件。工具参数不会触发执行或授权，未知快照不直接输出。
- 按完整 `eventId` 去重。同一 sequence 下的不同 ordinal 均消费；界面更新成功后才提交内存游标。
- 断线保持已收到的回复，“重连原任务”使用原请求体、原 runId 和 `Last-Event-ID`，不自动创建新任务或回退旧接口。
- 收到文本结束或工具结束不代表任务结束；收到 `RUN_ERROR` 立即终止，忽略后续事件。取消、interrupt、审批等待与正常结束分别展示。
- “停止本轮”调用服务端 cancel 命令；失败重试复用 `request_id`，服务端确认终态前不宣称停止成功。
- 页面内切换会话只中断本地订阅，不发服务端取消命令。成功、失败、取消、卸载和退出登录均清理流资源。
- 悬浮反馈显示 5 秒且可手动关闭；模式选择器、输入和任务状态保留可访问性标签。

## 当前边界（接口同步后再完善）

- 仅纯文本新对话。新模式暂不开放文件上传、结构化澄清提交、审批提交、补充资料/复核恢复；标准模式原有功能不变。
- 审批只展示等待状态，不调用旧文本审批，也不同时订阅旧 durable 事件流。需要冻结审批/恢复后的事件接续策略后再开放。
- 重连上下文只保存在当前聊天页面内存；离开聊天页面导致卸载或刷新后不承诺恢复。未写浏览器持久化缓存，也未构造 tenant 前缀。
- public threadId 与历史内部 sessionId 尚未冻结映射，因此实验会话暂不开放历史删除、消息删除或会话归档，且不启动旧 session 任务轮询。
- 本轮用本地协议样例与组件测试验证，不代表真实后端端到端联调通过。

## 首轮 AG-UI 接入验证

- 全量前端测试通过：84 个测试文件、646 项测试。
- 新模式相关专项测试通过：协议解析、运行状态及聊天界面共 48 项；覆盖精确游标重连、终态截断、取消确认、审批等待和流资源清理。
- 生产构建通过；构建仍提示部分产物超过 500 kB，未在本轮扩展打包优化。
- 改动格式检查通过。尚未进行真实后端联调、浏览器人工验收或部署。

## 真实流式接收 + 前端轻量打字机（2026-09-21）

### 实现范围

- 仅网页端 AG-UI 当前最后一条助手回复启用打字机。标准模式仍直接展示收到的文本，后端、手机端和实验开关未改动。
- SSE 接收、原文入消息状态、事件去重、重连游标和运行状态保持原链路；`useTypewriter` 只保存展示进度，不参与协议或消息持久化。
- 活跃回复按约 32 毫秒间隔分批展示，积压时自动加速。后端结束立即更新任务状态，前台剩余动画在约 600 毫秒内收尾，并明确显示“回答已生成，正在显示”。
- “直接显示全部”仅跳过本条回复的动画，后续片段直接显示，不调用取消接口；长回复同步展开。原有“停止本轮”仍是独立的服务端取消操作。
- 失败、取消、中断、断线或等待审批时立即展示已收到内容并停止动画。重连只动画显示新增片段，历史消息、切回会话和已收到的内容不重新播放；开始下一轮时上一条回复也立即完整展示。
- 表格、代码、HTML 等复杂标记、下载卡片、知识草稿及结构化结果直接展示。超 20,000 UTF-16 代码单元的长文本或浏览器不支持原生字素分割时也直接展示，不延长等待。
- 使用浏览器原生字素分割保护中文、组合字符与表情；不截断已生成的 HTML。继续使用 `marked` 与 DOMPurify，对当前展示文本完整解析和安全过滤，并缓存未变化的 Markdown 渲染结果。
- 减少动态效果或页面进入后台时直接展示已收到内容；恢复前台不重播。动画帧、媒体查询监听、页面可见性监听和尺寸观察器在停用/卸载时清理。
- 距底部 64px 内跟随回复高度变化；用户上翻后停止自动下拉，提供“回到最新”。会话切换重置跟随状态。滚动行为同时改善标准模式，未修改其接收协议。
- 逐字内容关闭自动播报，保留稳定的展示状态提示；复制使用完整消息原文。继续复用现有 UI 组件，无新增项目依赖。

### 验证与边界

- 专项测试：5 个文件、79 项通过，覆盖 SSE/AG-UI 终态与重连、打字机、Markdown、完整原文复制、用户上翻、尺寸变化跟随及资源清理。
- 全量测试：85 个文件、669 项通过；类型检查与生产构建通过，原有大体积产物提示仍存在。
- Ant Design 检查：消息组件无问题；聊天窗口保留原有 4 处静态 notification 提示，本轮新增按钮无问题。
- 未进行真实后端联调、浏览器人工验收、部署或默认模式切换。前端不会将一次性后端返回变成真实后端增量输出；首字延迟及连续性仍需接口同步后实测。

## 后续切换前检查

1. 在联调环境启用后端新架构和前端实验入口，验证鉴权、代理 SSE 缓冲、首轮创建、同会话多轮、精确重放及真实取消终态。
2. 确认 public threadId / 内部 sessionId / 历史消息 ID 映射，以及上传后返回 ID 的归属。
3. 冻结审批/恢复后的事件模式、结构化 metadata schema 与工具参数分片语义，再开放对应操作。
4. 补齐刷新恢复、审批到期、并发审批、等待补充数据、租户/账号切换和慢网测试。
5. 完成网页浏览器实测与产品验收，再单独决定默认模式、正式上线和手机端适配。不能仅因设置前端开关就宣称完成后端切换。
